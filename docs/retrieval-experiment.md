# 关键词检索 vs 向量检索：动手实验

本实验使用项目已有的 `POST /search` 接口，比较同一批知识片段在两种检索模式下的结果。

## 1. 准备数据

1. 启动后端和前端。
2. 在前端上传 `samples/employee-handbook.md`。
3. 如果要测试向量检索，先在后端配置有效的 Embeddings API（`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`EMBEDDING_MODEL`），再上传样例文件。
4. 在文档列表确认该文档的 embedded chunk count 大于 0。若为 0，当前只能测试关键词检索。

> 注意：此前已上传但没有向量的旧文档不会自动补向量。配置 Embeddings 后请重新上传样例文件，避免误以为已有文档自动完成向量化。

## 2. 用相同问题分别检索

打开 `http://localhost:8000/docs`，找到 `POST /search`。每个问题分别提交两次，只改变 `mode`：

- `keyword`：强制关键词检索
- `vector`：强制向量检索
- `auto`：默认策略，有可用向量时走向量，否则回退关键词

每次请求的 JSON 示例：

```json
{
  "query": "员工请假可以休几天？",
  "limit": 5,
  "mode": "keyword"
}
```

向量检索时把 mode 改为 `vector`。接口响应中的 `mode` 字段用于确认实际检索模式。

## 3. 建议测试问题

| 问题 | 预期命中内容 | 测试目的 |
|---|---|---|
| 年假可以休几天？ | 年假制度 | 关键词直接命中 |
| 员工请假可以休几天？ | 年假制度 | 同义表达 |
| 出差回来后，多久之内要交票据？ | 差旅报销 | 口语表达与文档措辞不同 |
| 公司电脑离开座位要做什么？ | 设备与信息安全 | 语义表达 |
| 能不能把客户资料传到个人网盘？ | 设备与信息安全 | 否定/规则类语义 |

## 4. 记录结果

对每个问题记录：
- Top 1 是否命中预期章节
- Top 3 是否包含预期章节
- 返回的分数和排序
- 检索模式（keyword / vector）

建议重点观察“员工请假可以休几天？”和“出差回来后，多久之内要交票据？”：它们的提问措辞与原文并不完全一致。

## 5. 如何理解结果

- 关键词检索擅长精确词语匹配；问题与原文用词差异较大时，容易漏召回。
- 向量检索通过 Embedding 表示语义，可能找出措辞不同但含义相近的片段。
- 向量检索不是事实判断器，也不保证每题都比关键词检索好。模型、分块、语料规模和问题表达都会影响结果。
- 当前项目的关键词算法是简单子串匹配，向量检索是本地 SQLite JSON 向量 + Python 余弦相似度；这只是教学对照，不代表生产级检索系统。
